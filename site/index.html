04 / HOW I BUILD ENGINEERING PHILOSOPHY & APPROACH

Under the hood: how I think, build and learn.

Software engineering is more than typing syntax; it is how you reason through ambiguity, isolate elusive bugs, and prioritize maintainability as an engineering metric.

01 // WHAT I ENJOY BUILDING ARCHITECTURE

End-to-End Cohesive Systems

I thrive on projects where every layer snaps together cleanly—from the frontend user interaction and business logic in C#/ASP.NET Core down to the relational database tables on TiDB Cloud. I equally enjoy physical computing: wiring micro-controllers (ESP32/ESP8266) to ultrasonic and vibration sensors, and watching physical events trigger digital workflows.

02 // PROBLEM-SOLVING APPROACH FIRST PRINCIPLES

Decomposition & Root-Cause Isolation

When confronted with an elusive bug or complex feature, I resist speculative patching. I strip away layers, construct minimal isolated reproducible test scripts, inspect HTTP payloads and database query plans, and verify state transitions deterministically before modifying production code.

03 // TECHNICAL STRENGTHS COMPETENCIES

Algorithmic Thinking & Disciplined Craft

My competitive programming background instills rigorous complexity awareness ($O(V+E)$ graph algorithms, tree traversals, and dynamic programming). Combined with Clean Architecture patterns, this allows me to write code that is not just fast, but readable, testable, and maintainable.

04 // LEARNING DIRECTION HORIZONS

Distributed Systems & Low-Level Internals

I am actively expanding my understanding of distributed consensus, message queues, Linux operating system internals, and high-concurrency database indexing. I view every semester and open-source project as a stepping stone toward building fault-tolerant infrastructure.
